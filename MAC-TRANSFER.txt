Перенос проекта на Mac

1. Распаковать Test-mac-source.zip в локальную папку.
   Архив содержит исходники коммита, но не историю .git.
   Историю можно перенести отдельно, скопировав .git из проекта.
2. В Unity Hub установить Unity 6000.6.7f1
   (ProjectSettings/ProjectVersion.txt).
3. Добавить корневую папку с Assets, Packages и ProjectSettings.
   Нужен интернет для восстановления пакетов. Дождаться импорта.
4. Открыть Assets/MountainDrive/MountainPass.unity и проверить Play Mode.
5. Для сборки выбрать профиль macOS.

Сохранены игровые Assets и .meta, Packages и lock-файл,
ProjectSettings, исходные Models, SourceAssets, AgentScripts и docs.
Версии редактора и пакетов не менялись.

Library, Temp, Logs, UserSettings, work, .firecrawl, Assets/work,
Assets/_Recovery и файлы IDE в архив не входят. Они остаются локально
на Windows: Unity открыт, а массовое удаление отклонено автоматической
проверкой безопасности. Эти папки для переноса не нужны.

Проверка структуры: нет конфликтов регистра путей, у файлов Assets
есть .meta; нет локальных зависимостей пакетов, .blend и нативных
плагинов Windows в Assets. Фактический импорт, компиляция и запуск
на Mac ещё не проверены. Это не гарантия совместимости конкретного Mac.

Remote Git не настроен, коммит остаётся локальным.
Некоторые исходные ZIP моделей больше 100 MiB; для публикации на
GitHub отдельно потребуется решить хранение больших файлов.

Дополнительная проверка GUID:
Дубликатов GUID ассетов нет. В Assets/Settings/DefaultVolumeProfile.asset
обнаружены 4 ссылки на отсутствующие скрипты: OutlineVolumeComponent,
TestAnimationCurveVolumeComponent, OasisFogVolumeComponent, TestVolume.
В Assets/Settings/PC_Renderer.asset не разрешены 7 ссылок старого блока
probeVolumeResources (отладочные шейдеры/mesh/texture).
Это существовавшие до очистки ссылки; настройки не изменялись.
Их влияние требует проверки после импорта в Unity; отсутствие
предупреждений или ошибок при импорте не подтверждено.
