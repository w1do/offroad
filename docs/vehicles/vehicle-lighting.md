# Общие фары машины

30.10.2026. Реализация по запросу пользователя; настройки силы света и времени
срабатывания — калибровка прототипа, не паспортная фотометрия Pajero.

`VehiclePhysicsProfile.lighting` ссылается на `VehicleLightingProfile`.
`VehiclePhysics.Lighting` предоставляет общий компонент `VehicleLighting`.
Он не прикладывает сил и не зависит от марки, числа колёс или числа ламп.
Изменяемые режим, запрос дальнего, запрос туманок и задержка автоматики хранятся
на экземпляре машины. Общие assets во время движения не изменяются.

По умолчанию:

- F — цикл АВТО → ВКЛ → ВЫКЛ.
- K — включить/выключить ближний. Из дальнего переключает на ближний.
- T — включить дальний; повторное нажатие возвращает ближний. Дальний заменяет ближний.
- G — включить/выключить противотуманки. Если основные фары погашены,
  включение туманок также включает ближний.
- В режиме АВТО при Daylight ≤ 0,35 свет включается, при ≥ 0,6 выключается.
  Устойчивое изменение должно продержаться 2 секунды; при запуске ночью свет
  включается сразу. Значения доступны в профиле. В дождь туманки автоматически
  включаются только при явном включении Automatic Fog In Bad Weather.

HUD показывает фактический свет, режим автоматики и запросы водителя.
Под строкой света находятся кнопки «Ближний», «Дальний», «Туманки», «Авто».
Ручные команды включают свет сразу, в том числе днём; «Авто» возвращает
управление освещённостью. Кнопки и клавиши используют API общего VehiclePhysics:
SetLowBeam(bool), SetHighBeam(bool), SetFogLamps(bool),
SetHeadlightMode(VehicleHeadlightMode), CycleHeadlightMode().
Фактические состояния доступны через LowBeamOn, HighBeamOn, FogLampsOn.
Методы возвращают false при отсутствии настроенной системы фар.
Все клавиши конфигурируются, Key.None отключает соответствующую клавишу.
Ввод проходит через общий VehiclePlayerInput и учитывает externalControl.
Для AI доступны SetMode, SetHighBeam, SetFogLamps; Evaluate позволяет подключать
другую модель окружения. В данной сцене яркость передаёт ForestDayNightWeather.Daylight.
Если его нет, используется свет RenderSettings.sun или ambientSkyColor.

## Подключение другой машины

1. Создать Lighting profile или отдельную копию через инспектор VehiclePhysicsProfile.
   Настроить цвет, силу света в канделах, дальность в метрах, углы, cookies, тени,
   клавиши и пороги автоматики. Профиль можно редактировать там же встроенно.
2. На VehiclePhysics нажать «Подключить общую систему фар».
   При наличии профиля компонент также добавляется автоматически при Initialize.
3. В VehicleLighting назначить Lamps произвольной длины. Каждая запись — тип
   LowBeam / HighBeam / Fog и Light в родном месте фары. Позицию и направление
   задаёт Transform, локальное +Z света направлено вперёд пучка.
4. Можно создать стартовый шаблон из шести Spot Light по BoxCollider кузова.
   Это только шаблон двух передних фар каждого типа: сверить места и наклоны
   по конкретной модели. Runtime не ограничен шестью лампами.
5. Lens необязателен. Назначать только отдельный renderer свечения стекла;
   компонент включает/выключает его. Нельзя назначать объединённый кузов или
   исходный renderer стекла, который должен оставаться видимым при выключении.
   Один renderer может использоваться одновременно привязками ближнего и дальнего.

У Pajero свечение использует производные меши именно передних поверхностей
исходных Object_33/32 clearglass, с сохранением формы и UV и малым смещением
для устранения z-fighting. Исходная импортированная модель не изменена.
Отдельные круглые накладки, замеченные пользователем, удалены.
Названия стекол и координаты Pajero существуют только в редакторском
AgentScripts/ConfigureVehicleLighting.cs, не в общем Runtime.

Cookies создаются локально: смягчённая верхняя граница ближнего, узкий дальний,
широкая низкая полоса туманок. Это приближение, не сертифицированная оптика.
В LivingForest и ForestLightSnow добавлены варианты _CLUSTER_LIGHT_LOOP,
_ADDITIONAL_LIGHT_SHADOWS и _LIGHT_COOKIES: используемый PC renderer работает
в Forward+, без этих вариантов штатный лес не получал корректный свет фар.
Версии pipeline, пакетов и режим рендеринга не менялись.

## Выполненные проверки

Unity Editor 6000.6.7f1, Unity CLI 1.0.0-beta.14, установленный Pipeline 0.9.1.
Recompile: 0 ошибок и 0 предупреждений. Настройка сцены выполнена через Editor
в Edit Mode; runtime-проверки — через уже открытый Editor в Play Mode.

```powershell
unity recompile --project-path E:/Unity/Test --json
unity command editor.playmode stop --json
unity command script run --file AgentScripts/ConfigureVehicleLighting.cs --entry ConfigureVehicleLighting.Main --project-path E:/Unity/Test --json
unity command editor.playmode start --json
unity command script run --file AgentScripts/ValidateVehicleLighting.cs --entry ValidateVehicleLighting.Main --project-path E:/Unity/Test --json
unity command script run --file AgentScripts/CaptureVehicleLighting.cs --entry CaptureVehicleLighting.Main --project-path E:/Unity/Test --json
```

Последняя команда планирует съёмку на нескольких отрисованных кадрах; дождаться
обновления `docs/reports/vehicle-lighting-render.json` и проверить passed.
Отчёт логики: `docs/reports/vehicle-lighting.json`. Проверены начальное включение
ночью, выключение днём, задержка, гистерезис, ручное ВЫКЛ, ближний/дальний,
туманки, независимые тестовые экземпляры с 3 и 9 лампами, выключение компонента
и неизменность общего профиля. Это проверка универсальной схемы, не испытание
второй художественной модели автомобиля.

Снимки: `work/vehicle-lighting/off.png`, `low.png`, `high.png`, `fog.png`,
`day-front.png`, `night-front.png`. Каждый ночной режим увеличил измеренную яркость
области дороги относительно выключенного света. Дневной вид проверен на отсутствие
лишних точек; в сцене осталось 0 объектов Dedicated lamp lens.

Полный ночной рейс, standalone-сборка и производительность дополнительных теней
на целевом ПК не проверены. Состояние фар пока не сохраняется между запусками;
новое включение компонента использует начальный режим из профиля.
